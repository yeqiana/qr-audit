# 离线、安全与数据保护

## 离线边界

- 不登录微信或其他扫码 App。
- 不上传图片或载荷到云端识别服务。
- 不访问二维码内容中的 URL。
- 不通过在线接口校验载荷。
- 仅使用本机已安装工具和已缓存模型。

如果当前环境的扫描器会联网、调用在线 API、下载模型或遥测，必须先停止该路径并说明原因；未经用户授权不得继续。

## 原始数据保护

- 原图目录只读；源码只读审计；历史报告只读。
- 每次运行新建唯一 run 目录。
- 临时图像写入 run 隔离目录；默认保留证据，不自动清理。
- 不使用危险清理命令，不覆盖现有 `qr-tools`。

## 路径安全

- 检查输出路径在 workspace/report 根目录内。
- 不跟随符号链接和 Windows junction 逃逸。
- 输出目录名和报告文件名进行安全规范化。
- 已存在的 run 目录拒绝覆盖。
- 工具导出目录若已存在且内容不同，停止并要求用户处理；不覆盖。

## 结果边界

- `DETECTED_ONLY` 不是成功。
- `DECODED` 只代表离线解码器读出 QR 载荷。
- 微信是否支持必须有微信实扫证据；否则 `NOT_TESTED`。
- 业务是否可用必须有独立业务校验；否则 `NOT_VERIFIED`。
- 多解码器载荷冲突需要人工复核。
- 完整贡献度实验缺少任一预期组合时，独占贡献和移除损失为 `INCOMPLETE`，不能填 0。

## 分享报告

如果报告可能被分享，先检查载荷是否包含个人信息、凭据、访问令牌或私有链接。对外报告应脱敏；本地原始证据由用户自行控制访问权限。
