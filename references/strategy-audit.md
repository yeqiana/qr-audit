# 策略源码审计与贡献度定义

## 1. 审计事实等级

| 等级 | 含义 |
|---|---|
| `SOURCE_CONFIRMED` | 当前源码中找到明确实现、调用位置和参数 |
| `RUNTIME_CONFIRMED` | 本次运行日志/attempt 证明策略实际执行 |
| `INFERRED` | 根据上下文推断，但没有直接证据 |
| `NOT_VERIFIED` | 源码不可读、依赖/API 不确定或没有运行证据 |

源码中存在函数不等于本次运行调用了它。配置文件中有参数不等于运行时加载了它。

## 2. 每条策略审计字段

strategy_id、显示名称、策略家族和标签；真实实现文件/类/函数/行号；输入与输出图像尺寸；参数名、值、单位、默认值和覆盖来源；执行条件、调用顺序、是否可并行；解码器及选项；可能损坏模块边缘的风险；适用图片特征；真实执行次数、成功/失败/跳过数；独立增量、重复成功、独占贡献、耗时；对应证据和复跑命令。

## 3. 28 条策略基线

以 `assets/strategy-registry.initial.json` 为唯一初始列表，ID 固定为 V01–V28。名称和顺序来自用户提供的清单，不代表实现已经核实。

需要特别审计：

- 自动对比度到底是线性拉伸、直方图均衡、CLAHE 还是其他处理；
- Otsu、自适应阈值的具体参数；
- 最近邻/普通放大的实际插值方法；
- 白边的像素宽度、模块宽度估算方式、最大尺寸限制是否包含边框；
- 固定阈值的灰度空间、阈值比较符和通道；
- 模块采样是否先定位二维码网格，还是仅按固定比例缩放；
- 纯码模式实际绑定到哪个解码器/API、当前版本是否支持；
- 反色/旋转/降采样是否已经由解码器内部选项执行。

未知参数保持 `null`，不得猜测。

## 4. 指标定义

设策略 i 的成功图片集合为 Sᵢ，策略执行顺序为 1…n：

- `success_images(i) = |Sᵢ|`
- `ordered_new_success(i) = |Sᵢ - union(S₁…Sᵢ₋₁)|`
- `repeat_success(i) = |Sᵢ ∩ union(S₁…Sᵢ₋₁)|`
- `exclusive_contribution(i) = |Sᵢ - union(Sⱼ, j ≠ i)|`

`exclusive_contribution` 只有完整贡献度矩阵成立时才有效。常规扫描或不完整实验必须显示 `NA`。

### 整类策略移除损失

`removal_loss(G) = |union(Sᵢ for all i) - union(Sᵢ for i not in G)|`

应按 `family`、`tags` 或明确配置的策略类别分别计算。至少报告总体、图片组和目录侧损失。

**禁止推论：** 单条策略独占贡献为 0，不能证明其所属策略类别没有价值。例如多个纯码策略互相覆盖时，每条策略可能独占贡献为 0，但整个纯码分支移除后仍可能损失成功图片。

### 耗时

平均耗时为所有真实执行 attempt 的 duration_ms 算术平均；P95 使用最近秩法。跳过项不参与耗时统计。真实执行后报错的耗时默认仍计入执行耗时。

## 5. 删除/合并策略的决策门槛

本 Skill 不自动删除或合并策略。报告最多提出待人工评审建议。建议必须同时考虑完整贡献度实验、策略类别移除损失、困难样本子集、耗时/内存、解码器互补、载荷冲突风险和跨数据集复现。证据不足时结论只能是 `INSUFFICIENT_EVIDENCE`。
