# Evidence-first GEO and AI-search discoverability

GEO (generative engine optimization) here means making **QR Audit's real, bounded capabilities easy to discover, understand and accurately cite**. It does **not** claim any measured ranking, recommendation likelihood, search impressions, Google index status, or AI citations.

## Primary search intents

- Offline QR code scanner without a WeChat login
- QR image preprocessing strategy audit / benchmark
- ZXing-C++ OpenCV QR decoding comparison
- QR code scanner failure analysis and manual review reduction
- Evaluate 28 preprocessing variants with complete experiments
- QR preprocessing unique contribution and family ablation
- Generate reproducible QR scan Markdown and HTML reports
- Codex / Claude Code Skill for local QR code auditing

## Discoverability assets

- Bilingual titles and human-readable summaries in English `README.md` and `README.zh-CN.md`.
- Clear implementation boundaries in the top fold: **3 implemented variants**, **28 registered**, **no proven WeChat parity**.
- Search-intent-aligned FAQ, comparison, metrics example and reproducible Windows walkthrough.
- A canonical repo URL and navigable internal Markdown links.
- Versioned Skill entry, provenance and evidence contracts.
- No fabricated adoption stats, citations, testimonials, benchmarks, rankings or “100% success” claims.

## Reproducible assessment (before and after changes)

The file [`evals/discovery-baseline.md`](../evals/discovery-baseline.md) contains fixed discovery prompts and observation rules. A human reviewer should record date, engine, account/region, exact query, top visible sources, whether `yeqiana/qr-audit` was independently discovered, whether the answer accurately states V01–V03 versus V01–V28, and whether the citation is to canonical content.

Do not treat merely writing a FAQ or adding topics as a visibility improvement. Actual ranking, index state and AI citations require repeat observations in live search products.

## No SEO mythology

Google's official [Guide to Optimizing for Generative AI Features](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) stresses helpful unique content and continuing to follow foundational SEO guidance. It explicitly cautions against treating unnecessary AI-specific text files, mechanical content chunking or inauthentic mentions as guaranteed advantages.

GitHub's [repository topics guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics) says topics help repository discovery. Suggested topics are listed separately for a maintainer to configure; **a Markdown document does not change GitHub metadata**.
