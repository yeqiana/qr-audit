# qr-audit v2.0.0-ai.3：RS 擦除纠错与低分辨率逆向采样实验

> 独立实验分支 `experiment/qr-module-recovery-v2`，从 v2.0.0-ai.2（本地提交 `505bc5e`）隔离派生。此方案**不属于正式发布或真实场景成功率承诺**。

## 目标与事实边界

上一版在同一固定合成图集完成 158/160 张正确识别、80/80 对；剩余 2 张有完全不同的破坏模式。第三阶段使用独立恢复策略，并将结果交由 ZXing-C++ / OpenCV 真实二维码解码器校验。生成真值只在测试计算对错时使用，**不会进入运行时算法的输入**。

### 方法 A：可见码字 + Reed–Solomon 字节擦除

针对裁剪静区和边缘模块的 G5/05-006 左图，外沿有 96 个模块不可见，但可见 529 个模块完全正确。采用以下受限实现：

1. 仅支持 QR **版本 2、纠错级别 M、单 RS 块**，其格式为 44 个总码字、28 个数据码字、16 个纠错码字；不把其他版本或等级伪装为已支持。
2. 在图像上独立读取 QR 格式信息（BCH 掩码及纠错级别），从可见图案获取模块网格，不依赖原始二维码 payload。
3. 遵照 QR Zigzag 扫描顺序移除掩码，将缺失模块对应的**整个码字**标记为擦除，不猜测缺失码字。
4. 基于 GF(256)（原始多项式 0x11D）求解有限的 RS 擦除方程；最多 16 个擦除码字，并检查全部 16 个校验综合式。校验失败、版本不支持或擦除过多即拒绝。
5. 重建标准 QR 模块图后，**必须由 ZXing-C++ / OpenCV 成功解码**，才能计为成功。

本机 G5/05-006 左图中，受影响的 15 个码字全部由 RS 擦除算法恢复，且重建后的图片通过 ZXing-C++ 正确解码。该功能**不修复其他已知值错误的码字**，也不假装实现任意版本的 RS。

### 方法 B：最近邻放大的逆向采样

针对 G7/07-004 右图，观察到真实图像是低分辨率数据经最近邻放大得到，因模块采样点误差导致约 92 个模块读取错误。

1. 对固定大小图像检查是否是**精确的最近邻放大复制**；只有每一像素重新投影完全相同时才进入逆向流程，不对任意照片作盲目锐化。
2. 仅在版本 2、正视方码、**4 个模块白静区、整数字符模块间距**的受限模型下估计缩放数据大小。
3. 使用 QR 固定功能图案作为**图像结构约束**，对观测数据建立面积采样的前向模型，利用本地 SciPy 有界 L-BFGS-B 拟合未知数据模块。模型输入完全是图像采样值，不读取任何载荷。
4. 对数值拟合结果进行损失阈值限制，再将候选 QR 交给真正的解码器，**只有解码返回载荷才成立**。

此次 G7 实验，推断出 36×36 的中间分辨率，恢复后的 625 个模块与生成真值一致，并由 ZXing-C++ 读取出正确文本。它不代表任意低分辨率二维码都能恢复；对 JPEG、模糊、非整数边框和真实透视照片很可能被严格跳过。

### 参数配置与资源限制

默认行为保持前版不变。新增可选开关：

```json
{
  "module_recovery": {
    "enabled": true,
    "max_version": 10,
    "top_k": 24,
    "max_decode": 48,
    "rs_erasures": true,
    "inverse_resample": true,
    "max_extra_decode": 12
  }
}
```

以上字段是原 `ai-model-config` JSON 的一部分，而不是独立的顶层文件。只在 `--ai-fallback` 已启用、原 V/R/B/A01 失败之后执行。原有 GPU 模型仍使用 RTX 3060、CUDA、640px、batch=1、workers=1；未启用超分模型。

- 每个候选必须先通过二维码固定图案与格式信息门槛。
- 单张输入不得超过 800 万像素；额外独立解码尝试最多 `max_extra_decode` 次，参数范围 1–24。
- `inverse_resample` 需要**现有本地 SciPy**；缺失时在扫描开始前明确拒绝，而不是静默变成低能力模式。
- 逆向重建使用本地 CPU 小矩阵优化，不会新增任何 GPU 模型。现有依赖仍由独立 venv 管理，不修改全局 Python。
- 输入图片、历史证据和此前的 AI 实验分支保持只读。所有成功内容只能来自真实扫码解码器，不能使用配对成员的载荷推断另一侧成功。

## 发布验证与进一步研究

每次运行必须完成：
- 新增 RS 单元测试：GF(256) 擦除、全部校验式、错码拒绝、真实 QR 模块重建、裁剪恢复；
- 逆向采样单测：真实合成缩放恢复、噪声/不适配图拒绝；
- 单图和配对零回退、负例误报、源码/输入 SHA、manifest、总览；
- Python 3.11 / 3.13 的 GitHub CI 及 Windows 本地单测；
- 保留最终 `run.py` 原始 evidence、真值对照 JSON、源文件指纹与 GPU 配置文件；
- 不修改 `main`，草稿 PR 的目标应是上一阶段实验分支。

真实图片推广前优先研究 QR 多版本/多 RS 块的数据交织、可见误码纠正、透视坐标重建及非最近邻超低分辨率恢复。同时需在真实 2560 张及历史 431 张/409 对成功集合上完成独立验证，并审查 QRDet/Ultralytics 授权；目前这些均未完成。
